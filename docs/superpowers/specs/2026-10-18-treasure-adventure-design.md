# 异步寻宝动画网站设计

## 目标

把附件 `treasure.js` 的 Promise 链式寻宝流程改写为 `async/await`，扩展为一个可以在浏览器中游玩的动画寻宝故事，并通过 Vercel 发布公开网页链接。

## 现有代码理解

附件定义了 `TreasureMap`，用四个返回 Promise 的静态方法模拟异步 API：获取图书馆线索、解读古文字、搜索神庙和打开宝箱。原流程通过连续 `.then()` 串联步骤，并在末尾统一 `.catch()`；搜索神庙时有 50% 概率遭遇守卫并失败。代码已在 Node.js 中运行，成功完成过整条链路。

## 方案选择

采用独立、无后端依赖的静态站点，而不是嵌入当前采购管理系统。页面用原生 HTML、CSS 和 JavaScript 实现，便于直接展示 `async/await` 教学重点、降低部署复杂度，并适合 Vercel 静态托管。

备选方案是把游戏写成 Vue 页面并加入现有 `web` 工程，或使用 Canvas 游戏引擎。前者会把作业与采购项目耦合，后者对当前短篇流程过重，因此不采用。

## 剧情与流程

故事扩展为“星潮遗迹”：

1. 在月光图书馆取得会发光的残页。
2. 异步解读星象密文，获得雾语森林坐标。
3. 穿越森林，玩家在岔路选择“萤火小径”或“古树密道”。
4. 抵达潮汐神庙，完成守卫谜题；错误答案会触发可恢复的异步失败，而不是直接结束整局。
5. 收集星钥、月印和潮汐水晶后开启宝箱。
6. 展示宝藏、冒险评级与重新开始入口。

剧情步骤均由返回 Promise 的函数模拟延迟、成功或失败；主流程 `findTreasure()` 使用 `async/await`、`try/catch/finally` 顺序调度。用户选择通过 Promise 等待按钮事件，让交互本身也属于异步流程。

## 页面与动画

页面采用深蓝夜空、金色遗迹与青绿色魔法光效的电影海报风格。桌面端为左侧探险地图、右侧故事日志，移动端纵向排列。

核心动画包括：背景星尘缓慢漂浮、地图路径逐段点亮、角色沿路径移动、线索卡片翻转、神庙门开启、宝箱抖动与金光粒子爆发。动画使用 CSS transform/opacity 和少量 JavaScript 状态类；尊重 `prefers-reduced-motion`，关闭系统偏好下的非必要动态效果。

页面提供“开始冒险”“作出选择”“重新开始”按钮、进度指示、实时剧情日志和错误恢复提示。按钮在异步等待期间禁用，避免重复触发；重新开始会取消旧流程，防止前一轮延迟结果污染新一轮状态。

## 代码结构

- `index.html`：语义化页面骨架、地图、故事面板和交互控件。
- `styles.css`：响应式布局、场景状态与动画。
- `treasure.js`：异步 API、流程控制、取消令牌、状态渲染和用户选择 Promise。
- `vercel.json`：静态站点路由与部署配置。

所有运行时数据保存在浏览器内存中，不采集用户信息，不需要数据库或服务端接口。

## 错误处理

每个异步步骤抛出 `Error` 对象并带可展示信息。主流程捕获错误，区分“可重试的剧情障碍”和“未知异常”；前者提供继续挑战，后者显示安全的失败提示与重新开始按钮。流程令牌用于忽略已经取消或过期的 Promise 结果。

## 验证与部署

在获得测试批准后，验证内容包括：

1. 异步主流程与成功、失败、重试、重新开始分支。
2. 静态页面脚本加载与基础交互。
3. Vercel 构建或静态部署结果。
4. 部署完成后的线上 URL 可访问性。

发布前用 Vercel CLI 确认当前登录身份和项目绑定，避免部署到错误账户或项目。首次部署需要用户已登录 Vercel；若出现设备授权流程，由用户本人完成。最终在聊天中提供公开链接。
