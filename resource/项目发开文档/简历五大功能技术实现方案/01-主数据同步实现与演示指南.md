# 主数据同步：当前实现与前端演示指南

日期：2026-10-17，分层结构更新于2026-10-18。本指南对应第一份同步方案，以及其依赖的基础调度能力。代码结构见[集成模块分层与代码阅读指南](00-集成模块分层与代码阅读指南.md)。CDC、Canal、BPA、采购验收推SAP和集中报价不在本次实现范围。

## 1. 前端入口

在系统顶部选择“外围系统集成”，进入“SAP 主数据同步中心”，地址为`/integration/sync`。

页面包含四块可操作区域：

- 指标和数据流：本地记录数、活动任务、告警数，以及拉取、落库、恢复的流程说明。
- 任务卡片：成本中心、汇率分别展示基线、游标、最近完整同步、计划和启停状态。
- 数据与运维：本地主数据、运行记录、成功页检查点、失败记录、对账差异与告警。
- 开发模拟源：维护SAP源记录、修改源版本、冻结/停用、启用和关闭503故障。

源端记录和本地记录来自不同schema。编辑模拟SAP后不会直接更新本地表，必须经过HTTP拉取与目标页事务。

## 2. 当前已编码的能力与后续范围

| 能力 | 本次实现 |
| --- | --- |
| 稳定增量游标 | `SOURCE_CURSOR`，每种实体单独变更流，固定本次上界 |
| 首次全量 | 源快照在源端事务中物化，并记录对应增量基准位置 |
| 基线期间变化 | 基线完成后继续从基准游标拉增量 |
| 分批和写入 | 默认500条/源页、200条/目标SQL，多VALUES Upsert |
| 页级恢复 | 业务数据、页审计、检查点同一目标事务提交 |
| 幂等与版本 | 业务唯一键、源版本条件更新、同版本内容冲突检查 |
| 多实例协调 | 数据库租约、心跳、token、写入前run和lease锁校验 |
| 调度与重试 | XXL-JOB自动触发与调度重试；人工任务持久化退避、失联恢复、取消与补偿 |
| 对账 | 固定源快照逐页比较实际目标字段；源端缺失仅报告 |
| 人工修复 | 独立REPAIR运行，可补齐目标缺失与修复相同/较旧目标版本，不覆盖较新版本 |
| 失败告警 | 失败记录、连续失败和滞后告警、去重待办、已读与自动恢复 |
| 邮件 | 尚未接入；界面明确说明，不伪称已经发送通知 |
| 时间窗口增量 | 保留在技术方案中作适配学习，目前没有实现第二套运行引擎 |
| CDC＋MQ、Canal | 后续独立练习，本次不安装、不部署 |

2026-10-18分层重构后，目标写入使用MyBatis Mapper/XML执行参数化多VALUES SQL，业务流程与事务位于Service。DAO实体统一DO后缀，请求与响应分别使用ReqDTO、RespDTO。页事务仍使用Spring `TransactionTemplate`，保持Upsert、检查点和页审计的原有原子性。SRM/STC模块保持原有实现。

检查点text字段保存JSON，包含`mode/sourceCursor/snapshotId/snapshotPosition/baselineCursor/upperCursor`；这只是本次稳定游标实现的状态结构。时间窗口方案中的完整水位和页内位置不混入当前运行模式。

## 3. 启动方式

### 3.1 使用现有完整项目

继续使用仓库已有的聚合启动脚本：

```powershell
.\scripts\run-monolith.ps1 -SkipInfrastructure
```

前提是PostgreSQL及项目已有中间件已经启动，且`.env`匹配本地连接。脚本会构建代码并加载新页面；如果自己设置了跳过构建选项，要先更新前后端构建产物。后端聚合入口现在额外迁移`integration_schema`，不会把模拟源表放进SRM/STC schema。

前端单独运行时仍默认通过网关8080访问聚合服务8090。聚合与微服务两套网关配置都已增加`/api/integration/**`路由；仅重启前端无法让旧网关和旧后端加载新代码。

### 3.2 仅启动同步模块

在`backend`目录中，确保当前进程加载了`.env`里的数据库环境变量，再执行：

```powershell
mvn -pl integration-service -DskipTests spring-boot:run
```

默认端口8086。独立服务默认开发profile会启用模拟SAP；数据库连接可配置`INTEGRATION_DB_URL/INTEGRATION_DB_USER/INTEGRATION_DB_PASSWORD`，否则使用本机5433的procurement库及项目默认开发账号。真实环境应显式指定profile和连接，不能使用默认开发凭证。

前端在`web`目录可指定代理直接指向该服务：

```powershell
$env:VITE_DEV_API_PROXY = 'http://localhost:8086'
npm.cmd run dev
```

这样无需启动网关即可观察同步页，但其他业务域的页面不由这个独立服务提供。前端使用当前Vite要求的兼容Node版本；本机旧Node可能出现版本警告，优先使用Node 22或24环境。

### 3.3 隔离联调端口

本次验证使用集成8096、前端5196，未重启原业务进程；自动Cron关闭，由接口或页面手动触发。该验证实例配置了专用开发管理密钥，在页面“管理密钥”中输入`sync-local-validation`即可维护模拟源和触发运行。它仅用于本机演示，不是项目生产密钥。

验证实例停止后可以按3.1或3.2自行启动；正常开发profile未配置`INTEGRATION_ADMIN_KEY`时不要求输入这个验证密钥。

## 4. 建议演示顺序

1. 进入同步中心，查看两个任务、真实记录数与当前检查点。空库时显示“待首次全量”，开发源默认有3条成本中心及3条汇率。
2. 点击“首次全量同步”，打开运行抽屉，查看BASELINE及随后DELTA阶段的成功页和游标。再次触发时只处理后续变更。
3. 切换“SAP 源端模拟”，新增一个成本中心，例如`RD_DEMO_01`；此时本地列表不应自行出现。
4. 点击成本中心“拉取增量”，在详情中观察真实应用数量，再回到本地列表搜索新编码。
5. 编辑同一源记录名称、冻结或停用，重新拉增量，确认源版本递增、本地仍是同一业务行。
6. 修改同一生效日的汇率数值，再拉汇率增量，确认同一业务键更新而非新增重复行。
7. 新增一个源端记录但暂不拉增量，执行“只读全量对账”，查看MISSING_TARGET差异；随后“对账并修复”，填写原因并查看修复结果。
8. 在模拟源启用503故障，触发同步，查看RETRY_WAIT、下次重试时间与错误记录。连续3次失败产生告警，最终最多自动执行5次。
9. 关闭503故障；可以等待下次自动重试，或取消等待中的任务，再通过“失败补偿/重试”新建关联运行。追赶成功后相应失败/滞后告警自动恢复。

UI里的“业务执行开关”是SRM侧的执行保护开关：关闭后，XXL-JOB即使按Cron发起回调，也会得到`JOB_DISABLED`，但不会强制中断已经运行的任务。Cron表达式和调度启停由XXL-JOB Admin维护。基线快照超过24小时未完成时，会明确失败；取消活动任务后可“重建未完成基线”，不删除已落库记录。完整基线不允许通过这个入口任意重置游标。

## 5. 配置与环境边界

| 配置项 | 用途 |
| --- | --- |
| `integration.sync.page-size` | 上游页大小，默认500，允许1～1000 |
| `integration.sync.write-batch-size` | 每SQL写入条数，默认200，允许1～500 |
| `integration.sync.max-attempts` | 自动执行次数，默认5 |
| `integration.sync.lease-seconds` | 租约长度，默认60秒，15秒心跳 |
| `xxl.job.enabled` | 是否在当前进程注册XXL执行器；业务Cron统一由XXL-JOB Admin管理 |
| `xxl.job.admin-addresses` | XXL-JOB Admin注册地址，开发环境默认`http://localhost:9090/xxl-job-admin` |
| `xxl.job.executor.*` | 执行器AppName、注册地址、9999端口及日志目录 |
| `integration.management.enabled` | 管理写操作总开关，非开发默认关闭 |
| `integration.management.admin-key` | 可选管理密钥，对应请求头X-Integration-Admin-Key |
| `integration.mock-sap.enabled` | 模拟SAP启用开关，非开发默认关闭 |
| `integration.mock-sap.jdbc-url/username/password` | 模拟源独立连接池；本地默认共用实例与开发账号 |
| `integration.mock-sap.api-key` | 内部模拟提取接口认证；与页面管理密钥分开 |
| `integration.sap.base-url/api-key` | 替换外部HTTP主数据适配接口，不声称已实现真实JCo联通 |

集成读写使用`integration_schema`，模拟源使用`mock_sap_schema`和独立连接池。生产需为它们分配独立账号及schema权限；本机开发账号共用不等于已经实现数据库账号隔离。

当前身份服务仍是开发身份；模块提供写操作总开关和可选密钥，尚未接企业RBAC、密钥管理或审计身份。这是本地复现范围，不作为可直接公网部署的安全实现。

模拟汇率契约：DIRECT的规范化值=`rawRate×toFactor/fromFactor`；INDIRECT=`toFactor/(rawRate×fromFactor)`。源端和SRM都校验该契约，目标表示“1原币等于多少目标币”。接真实SAP必须重新确认字段和因子语义，不能把此公式直接套给未经确认的UKURS。

## 6. 联调脚本

以下脚本会写入明确标注的模拟样例，运行前仍须取得用户批准。

```powershell
.\scripts\verify-master-data-sync.ps1 -BaseUrl 'http://127.0.0.1:8096' -AdminKey 'sync-local-validation' -IncludeRetryAlert
```

覆盖全量、修改增量、停用、源端并发版本冲突、运行幂等、同生效日汇率修订、只读对账、修复、503连续失败告警与人工补偿。保留`VERIFY_*`成本中心及`V_*`汇率类型，便于前端观察；恢复成本中心为可用状态，并在finally中恢复原故障开关。不执行压测、不修改原SRM/STC业务表。

`scripts/verify-sync-ui.mjs`使用Node 22+及独立无界面Edge/Chromium的CDP连接，通过真实页面表单新增`UI_*`源记录，触发增量并验证目标列表。截图生成到`.codex-runtime/`。该脚本不下载浏览器、不引入项目依赖，但需要事先启动独立浏览器调试端口，并设置`SYNC_ADMIN_KEY`。

## 7. 还不能声称完成的内容

- 真实SAP RFC/JCo、真实客户账号与生产网络联通。
- 时间窗口适配器、多线程分片和CDC/Canal链路。
- 邮件发送、生产权限认证、快照/变更日志自动保留策略。
- 大规模性能指标、多实例失效接管的完整故障演练。
- 当前新模块联调不能替代所有原业务回归测试。

模拟源快照24小时后不再供恢复使用，当前不自动删除其物理历史；大规模或长期运行前应补充有明确保留期限和安全边界的清理任务。
