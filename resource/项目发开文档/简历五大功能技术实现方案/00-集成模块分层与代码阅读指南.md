# 集成模块分层与代码阅读指南

更新日期：2026-10-18。对应本次 SAP 主数据同步和 XXL-JOB 调度的分层重构。

## 1. 目录约定

Java 根包为 `com.example.procurement.integration`：

```text
integration
├── controller               HTTP 接口，不写 SQL
│   └── mock                 模拟源 HTTP 接口
├── service                  业务能力接口
│   └── impl                 业务流程、状态规则与事务
├── dao
│   ├── entity               数据库实体，统一 DO 后缀
│   ├── mapper               MyBatis 数据访问接口
│   └── typehandler          PostgreSQL UUID 类型绑定
├── dto
│   ├── req                  管理接口请求，ReqDTO 后缀
│   ├── resp                 页面及源接口响应，RespDTO 后缀
│   └── domain               外围传输数据和内部联查投影，DTO 后缀
├── domain
│   ├── context              JobContext、检查点、XXL触发上下文
│   ├── enums                主数据类型、触发来源、重试归属
│   └── result               内部提交和执行结果
├── config                   配置参数、线程池、MyBatis、XXL、模拟源基础设施
├── client                   SAP HTTP 客户端
├── job                      XXL入口、人工任务消费、心跳和恢复触发
├── security                 管理操作与源接口密钥校验
├── exception                业务异常和统一HTTP异常处理
├── support                  数据校验、汇率规范化、哈希、模型转换
└── mock
    ├── service/impl         模拟SAP业务
    ├── dao/entity           模拟源持久化对象
    ├── dao/mapper           模拟源专用Mapper
    └── infrastructure       独立数据源资源生命周期

resources
├── mapper/integration       SRM业务SQL XML
├── mock-sap-mapper          模拟源SQL，主SqlSession不加载
└── db                       原有Flyway迁移，未修改表结构
```

`dto/domain` 承载的是传输数据和查询投影；`domain` 承载执行上下文、枚举和内部结果。命名为 domain 不代表已经引入完整 DDD 架构。现有流程没有额外的 pipeline 抽象，故不创建空目录或多一层转发。

## 2. 各层职责

| 层 | 例子 | 负责什么 |
| --- | --- | --- |
| Controller | `IntegrationController` | 接收ReqDTO、访问检查、调用Service、返回RespDTO |
| Service | `SyncJobServiceImpl` | 请求幂等、业务开关、状态流转、重试归属 |
| Lease Service | `SyncLeaseServiceImpl` | run和lease锁校验、页级事务、续租释放 |
| Sync Service | `MasterDataSyncServiceImpl` | 全量基线、增量分页、固定上界与对账流程 |
| Persistence Service | `MasterDataPersistenceServiceImpl` | 页内去重、版本冲突、批次拆分、对账修复、检查点和审计编排 |
| Query Service | `IntegrationQueryServiceImpl` | 看板、主数据列表、运行详情，DO转响应DTO |
| Mapper | `CostCenterMapper` | 只声明持久化方法，SQL位于XML |
| Entity/DO | `CostCenterDO` | 数据库字段，不承载同步流程 |
| Source DTO | `SourceRecordDTO` | SAP HTTP契约，含业务内容、源版本和变更时间 |
| Response DTO | `JobRunDetailRespDTO` | 页面需要的运行、失败页、差异明细 |
| Domain Context | `JobContext` | 当前runId、资源键、owner、token、执行次数 |

不再保留旧Repository实现，也不新增同义的PO、VO副本。响应统一采用RespDTO。

## 4. 建议代码阅读顺序

1. 先读 `controller/IntegrationController` 的提交和查询接口：只了解前端提交什么、收到什么。
2. 读 `service/impl/SyncManagementServiceImpl` 和 `SyncJobServiceImpl.submit`：理解人工请求如何成为持久化任务。
3. 读 `job/SyncJobExecutor.dispatch` 和 `JobExecutionCoordinatorImpl.executeClaimed`：理解领取、执行、落结果、释放租约。
4. 重点读 `MasterDataSyncServiceImpl.execute`：理解首次全量与增量分页。
5. 读 `MasterDataPersistenceServiceImpl.savePage` 和 `SyncLeaseServiceImpl.fenced`：理解一页数据、检查点和审计为何共同提交。
6. 对照 `dao/mapper/CostCenterMapper` 与 `resources/mapper/integration/CostCenterMapper.xml`：理解业务键、源版本和批量Upsert。
7. 再读 `job/XxlMasterDataJobHandlers` 和 `JobExecutionCoordinatorImpl.executeFromXxl`：理解XXL与人工入口复用业务、分开重试。
8. 最后读对账、告警、失联恢复，以及 `mock` 内源端快照和提交序号的实现。

## 5. 事务与数据源边界

SRM页事务依然使用Spring `TransactionTemplate`，只是事务内的数据库访问改为MyBatis Mapper。`SyncLeaseService.fenced`统一按run → lease加锁，然后调用页写入逻辑。在同一主数据源上，Mapper通过SqlSessionTemplate加入Spring绑定的事务，业务数据、检查点和页审计一起提交或一起回滚。

HTTP拉取SAP不放在该数据库页事务中，避免等待网络时长时间持锁。

模拟SAP的Hikari连接池、SqlSession和事务管理器由`MockSapConfiguration`单独装配。资源包装类不向Spring暴露第二个主DataSource/SqlSessionFactory，避免影响Boot业务数据源自动装配。源端变更序号分配、记录修改和变更事件仍在同一个源端事务内完成。

聚合模式与独立模式都会扫描`IntegrationMybatisConfiguration`，因此两种模式均可加载业务Mapper。模拟源Mapper不在主扫描包中，其XML也不在主Mapper资源目录中。

## 6. 验证范围

本轮测试与聚合打包已获得用户批准。新增定向测试覆盖Mapper XML解析、源/目标资源隔离、UUID参数映射、人工请求幂等、XXL重复/繁忙请求、租约换主隔离、页事务提交和检查点失败回滚。最终结果见本轮重构验证记录。

数据库SQL实际执行、启动装配、真实XXL回调与页面联调需要独立运行验证，不能用单元测试和打包结果替代。
