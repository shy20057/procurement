### 资料1：SRM系统 vs ERP系统【链接：https://www.cnblogs.com/xihong2014/p/14397884.html】

一、SRM系统

**SRM**全称是**供应商关系管理**，SRM系统是企业为方便管理与供应商日常往来的信息系统；企业通过上线应用SRM系统，可以达到优化与供应商的合作关系，提升业务部门的工作效率，降低采购及运营成本等目的。

![](https://pic2.zhimg.com/v2-0d46f41a89d0b07b301e9b313e717a45_b.jpg)

二、ERP与SRM的集成部分

1、采购寻源：在**ERP**下达采购需求后，将采购需求同步到SRM，由SRM通过采购寻源功能(采购询报价/采购竞价/招投标)，寻找合适的供应商及获取最优的采购价格，生成采购货源清单同步回ERP，ERP根据货源清单向供应商下采购订单；

![](https://pic1.zhimg.com/v2-715a72e792b8a53e962f8071ec2cb7b8_b.jpg)

2、订单协同：ERP将审核通过的采购订单通过接口同步到SRM，供应商在SRM对采购订单进行确认，如果供应商对于订单的交期或数量等有异议，可以通过SRM平台与采购部门磋商，最终无异议后确认采购订单，进入后续物流协同流程;

![](https://pic1.zhimg.com/v2-1f04f94f973515a7810963aa6d860ad8_b.jpg)

3、 物流协同：供应商按送货计划发货，在SRM系统发起送货通知，SRM通过接口将送货通知同步到ERP，由ERP完成货物的暂收、质检、入库等操作；质检、收货、退货数据还可以从ERP同步回SRM，以此作为SRM系统的供应商绩效考核的基础数据；

![](https://pic2.zhimg.com/v2-e55d0034224040c4e4655972e7008d79_b.jpg)



三、ERP与SRM各自功能划分

1、SRM[供应商关系管理系统]主要负责供应链上游管理系统，负责应商日常管理及供应商采购协同等，如供应商生命周期管理、采购寻源管理、采购协同管理等；

2、ERP[企业资源计划系统]主要是供应链中下游管理系统，负责企业内部业务流程的信息化管控等，如采购管理、库存管理、销售管理、财务管理等。

### 4.1 客户背景与业务链路

项目服务于晶圆制造企业芯恩（青岛）集成电路。用**设备备件采购**来说明订单协同流程。芯恩官网公开了 8 英寸和 12 英寸晶圆研发、生产业务，其采购岗位也列出了半导体设备零配件、洁净室和厂务系统等采购方向。本节结合资料 1 的采购寻源、订单协同两段及 SAP 官方资料梳理系统分工。芯恩项目的实际接口配置、日增量和可见时限需要以项目资料核实。 [芯恩官网](https://www.xinen.com/) · [芯恩采购工程师岗位](https://www.zhaopin.com/jobdetail/CC697011780J40898857103.htm) · [资料 1](https://www.cnblogs.com/xihong2014/p/14397884.html)

1. **ERP → SRM，传采购需求。** 设备部门在 ERP 提出备件需求。需要寻源的需求进入 SRM，带上需求单号和行号、物料、数量和要求到货日期。采购员向合格供应商发起询价，综合质量、交期、供货能力和报价后定标。
2. **SRM → ERP，回传定标结果。** 回传获选供应商、原需求单及行号、物料、议定单价、币种和约定交期。ERP 据此创建采购订单。本案例选择直接进入订单流程。SAP 官方的同类寻源集成也支持依据获选报价在 ERP 中创建订单、采购合同或计划协议。 [SAP 寻源定标集成](https://help.sap.com/docs/ARIBA_SOURCING/f2ab1e5180264bf686bcef6de607e263/rfq-and-award-integration-with-sap-ariba-sourcing?locale=en-us)
3. **ERP → SRM，发布采购订单。** ERP 完成订单审批，达到双方约定的对外发布条件后，由 SRM 同步正式订单。供应商登录 SRM，只能查看分配给自己的订单，并对数量、价格和交期作出确认或提出异议。
4. **供采双方确认。** 如果供应商无法满足要求交期，可以在 SRM 提出新的交期。采购员接受后，由 ERP 修改正式订单，并按审批规则重新发布；SRM 同步新版，供应商确认后进入物流协同。SAP 的供应商门户支持在采购方配置允许时提出交期、发货日期或数量调整。 [SAP 供应商订单确认](https://help.sap.com/docs/business-network-for-trading-partners/supplier-business-network-supply-chain/editing-shipping-dates-delivery-dates-or-quantity-when-creating-order-confirmation)

资料 1 把上游回传对象称为“采购货源清单”。如果这里指**接口传输的数据**，可以把中选货源和议定价格一起封装，本文称它为**定标结果**。SAP 标准的 **Source List（货源清单）**记录某工厂的某物料在指定期间可以向谁采购，可引用供应商或采购协议。物料和供应商对应的价格条件可以维护在采购信息记录或合同中。 [SAP 货源清单](https://help.sap.com/docs/PRODUCT_ID/af9ef57f504840d2b81be8667206d485/7b7fb65334e6b54ce10000000a174cb4.html) · [SAP 采购信息记录](https://help.sap.com/docs/SAP_S4HANA_CLOUD_PE/af9ef57f504840d2b81be8667206d485/4b7fb65334e6b54ce10000000a174cb4.html?version=2023.latest)

### 4.2 本次需求与工作边界

本节聚焦第 3 步，**将 SAP ERP 已发布的采购订单及后续变更同步到 SRM**。ERP 是正式订单内容和发布状态的权威来源，SRM 保存面向供应商的订单副本和协同反馈。第 4 步的查看、确认和提出异议说明同步数据如何被使用。寻源回传、ERP 审批流程、协同结果回写 ERP、送货、收货和开票是上下游背景。

同步对象为订单头与明细。订单头至少包含源系统、订单号、采购组织、供应商编码、币种、发布状态和对外发布版本。订单行至少包含行号、物料、数量、计量单位、单价和要求交期。首版按**整单快照**同步，每个订单含完整明细和发布版本，支持首次发布、改量、改价、改期、行取消、整单撤回或取消。ERP 草稿或待审修改不覆盖已发布版本，接口显式返回已发布订单的撤回或取消状态。

例如供应商打开 V1 时看到交期为 10 日。采购员在 ERP 把交期改为 8 日并发布 V2 后，SRM 更新订单。供应商若仍提交 V1 的确认，后端拒绝这次过期确认并提示刷新。数量、价格、交期等影响履约的字段变更后，对受影响的订单行重新确认。SAP 的同类规则也会按数量、交期、单价等字段判断是否保留旧确认。 [SAP 采购订单行变更与确认规则](https://help.sap.com/docs/business-network-for-trading-partners/supplier-business-network-supply-chain/purchase-order-line-items)

### 4.3 数据规模、实时性与方案取舍

- **日增量按订单行变化衡量。** 可用每日约 1,200 条订单行变化作容量评估样本，例如 200 张新发布订单、平均 4 行，加上 400 条已有订单行的变更。峰值按集中审批后多页订单同时待同步的场景评估。按整单快照拉取时，响应还会包含变更订单里的未修改行，分别记录业务变更量、拉取量和去重后的应用量。
- **用 10 分钟内在 SRM 可见作为方案评估目标。** 按每 5 分钟运行一次、保留 2 分钟安全延迟估算，正常进入可处理批次约需 2～7 分钟，剩余时间用于接口读取和写入。用“SRM 可见时间减 ERP 发布时间”衡量端到端延迟。供应商应答时间单独统计。作为行业参考，Cabot Microelectronics 手册中的 48 小时是供应商收到订单后的应答要求。 [供应商手册第 3.1 节](https://asset.fujifilm.com/www/us/files/2024-03/203b549347f79b736c58b8bebc5247e9/SupplierHandbook2021.pdf#page=20)
- **首版采用 XXL-JOB 定时调 ERP 增量接口。** 供应商确认场景采用分钟级目标，SRM 可以独立控制分页、重试和补拉。若未来确有秒级要求，且 SAP 或集成平台开放适用的采购订单事件，可改用事件通知，SRM 按订单号获取最新发布版本，MQ 用于投递、缓冲和消费重试。Canal 依赖可访问的 MySQL binlog，属于源端满足条件时的 CDC 方案。 [SAP 采购订单事件](https://help.sap.com/docs/SAP_S4HANA_ON-PREMISE/91af7f8d3acd47da90d33aaacfcd0d59/eeab037f56e24beeb5d729de18055a65.html) · [Canal 官方文档](https://github.com/alibaba/canal)

### 4.4 需求与技术实现

以下按订单同步的设计方案梳理。面试介绍实习交付时，以实际负责的接口、代码和联调记录为准。

| 需求 | 技术实现 |
| --- | --- |
| 首次初始化 | 从 ERP 接口按稳定边界分批导入已有的有效发布订单。记录初始锚点，基线完成后从锚点衔接增量，覆盖基线期间发生的发布和修改。 |
| 拉取新增、变更及取消 | 源接口按“对外发布记录修改时间 + 稳定唯一键”排序并支持组合游标查询。Mock 可沿用 `(updated_at, source_id)`，实际对接可在订单号于查询范围内唯一时采用 `(published_updated_at, order_no)`。首次发布、新版发布和撤回均需进入增量范围。SAP 有订单最后修改时间字段，是否覆盖上述状态以及支持所需过滤和排序，以实际接口契约为准。 [SAP 采购订单字段](https://help.sap.com/docs/SAP_S4HANA_CLOUD/bb9f1469daf04bd894ab2167f8132a1a/10d0eb23998e4622b50a5f2a84fba8e4.html) |
| 分页控制网络和内存 | 按整单分页，每次只持有一页订单和明细。页大小可配置，并同时观察明细行数和响应体大小，避免个别大订单把单页撑大。同一窗口按组合游标顺序取页。 |
| 处理峰值与线程池 | 日增量千级先用单流分页配合批量写入。若实测高峰批次无法在目标内完成，且 ERP 支持按采购组织等互斥维度查询，再通过有界线程池并行执行不同分区，各分区独立维护窗口、游标和检查点，并限制接口并发。 |
| 批量 Upsert 与防旧数据覆盖 | 使用数据库唯一约束和批量 Upsert。订单头按“源系统 + 订单号”识别，订单行再加行号。先判断入站订单版本，仅应用允许的更新。同版本重复到达可安全跳过，旧版本不修改新版及其明细。只有源接口明确提供同版本的完整明细时，才能根据其业务契约处理已移除行。 |
| 页级事务、重试和断点续传 | 一页的订单头、明细和检查点在同一事务内提交。该页写入失败只回滚该页，已提交页保留。重试使用原窗口和最后一个已提交游标。整个窗口完成后才推进完成水位。复用安全延迟与重叠回扫处理短时延迟可见的变更，更长时间的差异由对账发现。 |
| 定时调度与运行幂等 | XXL-JOB 定时触发，记录每次运行及结果。同一次调度投递使用稳定调度身份去重，同一数据流用租约防止定时触发、手动补拉同时写入。手动提交复用 `Idempotency-Key → run_id`。临时超时按重试策略处理，耗尽后可从失败记录发起补偿。调度幂等与目标表 Upsert 分别处理重复触发和重复数据。 [XXL-JOB 官方文档](https://www.xuxueli.com/xxl-job/) |
| 供应商可见与版本确认 | 后端以登录身份映射供应商编码，列表、详情和确认接口统一校验归属及发布状态。确认和异议记录与 ERP 订单副本分开保存，提交时带订单版本，后端在写入时校验仍是当前可确认版本。撤回、取消后关闭确认入口并保留操作历史。 |
| 定时全量对账与差异修复 | 低峰时对双方约定的已发布订单数据集做分页核对，比较订单号、发布版本、状态及关键行字段。先记录漏单、内容不一致或状态不一致，再按订单号从源端重新取证、补拉和修复。源端单次缺失先核查，避免把接口异常或权限变化当成订单取消。 |
| 日志、监控与报警 | 结构化记录运行 ID、窗口、页游标、拉取和写入条数、耗时、重试次数及错误码。用发布到可见的延迟、连续失败、积压和未修复差异作为告警指标。日志保留定位订单所需的标识，避免直接打印完整报价和接口凭证。 |

### 4.5 验收口径与面试表述

订单同步重点核验以下场景。

1. 一批订单发布后按页同步，同一时间戳的多张订单能跨页完整读取，供应商只能看自己的订单。
2. 已发布订单改量、改期或取消后，SRM 显示正确的最新版本。旧版本的确认请求被拦截，重放同一页不会产生重复记录或覆盖供应商反馈。
3. 模拟中途接口超时或目标写入失败。已提交页仍可查询，失败页和游标一起回滚，恢复后从断点继续。
4. 在约 1,200 条日变更样本及集中发布样本下记录端到端延迟、批次耗时和重复拉取量。若采用线程池，分别记录单流与分区并行的结果。人为制造漏单或版本差异，核验对账、补拉和告警记录。

日增量、时限和技术配置以项目记录为准。上面的 1,200 条和 10 分钟是方案评估用的样本与目标。口述时先讲订单协同业务，再讲自己实际负责的 SRM 侧工作，团队整体方案和个人交付分别说明。

**实习项目面试口述稿**

> 我实习时参与的是服务芯恩的采购协同项目，SRM 基于金蝶云苍穹开发，我参与了 SRM 侧的外围系统接口对接和数据同步。拿采购订单协同来说，采购员在 SRM 完成寻源定标，SAP ERP 根据定标结果生成订单，审批并发布后，供应商在 SRM 门户查看订单，确认数量和交期，也可以提出调整。这个环节的难点是订单发布以后还会改量、改期或取消，SRM 需要跟上 ERP 发布的有效版本，同时保留供应商对各版订单的确认记录。

技术追问可沿着「ERP 接口怎么提供增量 → SRM 如何分页和写入 → 失败从哪里继续 → 供应商如何确认当前版本」展开。组合游标、页级事务、XXL-JOB、差异对账和异常告警按项目中实际使用的方式讲述。
